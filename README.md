# Контур 18

Конкурсный fullstack-прототип для проекта «Инженеры будущего»: пользователь создаёт цифровой профиль, проходит учебную проверку возраста через симулятор Госуслуг и получает постоянный QR-пропуск.

> Симулятор `/gosuslugi` не является официальным сайтом Госуслуг и не отправляет данные во внешние системы.

## Возможности

- регистрация пользователя по ФИО и уникальному логину;
- вход в ранее созданный конкурсный профиль;
- защищённая HTTP-only сессия с HMAC-подписью;
- баланс учебного профиля;
- серверное подтверждение статуса 18+;
- постоянный уникальный `qr_token`;
- генерация QR-кода на сервере без сторонних API;
- QR-код доступен только после подтверждения возраста;
- адаптивный русскоязычный интерфейс в тёмной неоновой теме;
- PostgreSQL + Drizzle ORM;
- health-check и полностью автоматизированное Docker-развёртывание.

## Быстрый запуск

Требования: Docker Desktop либо Docker Engine с Compose v2, а также Node.js для автоматической генерации секрета.

```bash
./scripts/deploy.sh
```

Скрипт самостоятельно:

1. создаст `.env` с криптографическим ключом;
2. запустит PostgreSQL;
3. соберёт production-образ приложения;
4. применит схему Drizzle;
5. дождётся успешного `/api/health`.

После запуска приложение доступно по адресу [http://localhost:3000](http://localhost:3000).

Остановка:

```bash
docker compose down
```

Удаление контейнеров вместе с тестовыми данными:

```bash
docker compose down -v
```

## Локальная разработка без Docker для приложения

При запущенном PostgreSQL:

```bash
cp .env.example .env
npm ci
npx drizzle-kit push
npm run dev
```

Стандартный адрес базы из `.env.example`: `postgresql://postgres:postgres@127.0.0.1:5432/app_db`.

## Сценарий демонстрации

1. На главной странице выбрать «Регистрация».
2. Ввести ФИО, логин и принять условия.
3. В кабинете нажать «Подтвердить через Госуслуги».
4. На странице учебного симулятора нажать «Подтвердить и продолжить».
5. После возврата в кабинет QR-пропуск будет активен.
6. Для повторного входа использовать вкладку «Войти» и созданный логин.

### Слои

- `src/app` — маршруты App Router, серверные страницы и Server Actions.
- `src/components` — переиспользуемые элементы интерфейса и QR-компонент.
- `src/db` — подключение и декларативная схема Drizzle.
- `src/lib/session.ts` — подпись, чтение и удаление серверной сессии.
- `scripts/deploy.sh` — развёртывание без ручного редактирования исходников.

## Модель пользователя

Таблица `users` содержит:

| Поле | Назначение |
|---|---|
| `id` | числовой первичный ключ |
| `login` | уникальный логин |
| `full_name` | ФИО пользователя |
| `balance` | баланс, по умолчанию 1500 ₽ |
| `age_verified` | подтверждение 18+, по умолчанию `false` |
| `qr_token` | постоянный уникальный UUID-токен |
| `created_at` | дата создания профиля |

PostgreSQL выбран вместо файловой базы для безопасного параллельного доступа, контейнеризации и бесшовного production-развёртывания. Доступ к данным выполняется только через Drizzle ORM.

## Безопасность

- `.env` исключён из Git;
- cookie сессии имеет флаги `httpOnly`, `sameSite=lax` и `secure` в production;
- ID пользователя защищён HMAC-подписью;
- все изменения выполняются Server Actions;
- QR хранит случайный UUID, а не ФИО или дату рождения;
- проверка возраста раскрывает приложению только логический результат.

Для реального продукта учебный вход по логину следует заменить на ЕСИА/OAuth 2.0 или пароль/WebAuthn, а симулятор — на сертифицированную интеграцию с государственным провайдером идентификации.
